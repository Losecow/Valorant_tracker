# 발로란트 게임 트래커 (Valorant Tracker)

## 1. 프로젝트 주제 및 개요

- **주제**: 발로란트(Valorant) 개인 전적 및 플레이 기록 관리 프로그램
- **선택 이유**: 게임을 플레이하면서 매 판마다 어떤 요원을 선택했고, 어떤 맵에서 플레이했는지, 그리고 K/D/A(킬/데스/어시스트)와 헤드샷 비율 등의 성적이 어땠는지 체계적으로 기록하고 싶었습니다. 이를 통해 제가 주로 플레이하는 요원과 맵을 파악하고, 평균적인 실력(KDA, 헤드샷 비율)을 객관적인 수치로 확인하여 실력 향상에 도움을 얻고자 본 주제를 선정하게 되었습니다.

## 2. 데이터 필드 구성 설명 (`Valorant` 클래스)

게임 한 판의 기록을 저장하기 위해 총 8개의 필드로 구성했습니다.

1. `name` (String): 플레이한 요원 이름 (예: 제트, 레이나)
2. `map` (String): 플레이한 맵 이름 (예: 어센트, 헤이븐)
3. `kill` (int): 해당 판의 킬(Kill) 수
4. `death` (int): 해당 판의 데스(Death) 수
5. `assist` (int): 해당 판의 어시스트(Assist) 수
6. `headshotPercentage` (int): 헤드샷 적중 비율 (%)
7. `gameDate` (String): 게임을 플레이한 날짜 (예: 2026-05-02)
8. `trs` (int): Tracker Score (전적 검색 사이트 기준 종합 점수)

## 3. 클래스 구조 설명

- `Main`: 프로그램의 진입점으로, 사용자에게 콘솔 메뉴를 보여주고 입력을 받아 `ValorantManager`의 기능을 호출하는 UI 역할
- `ICRUD` (Interface): CRUD(Create, Read, Update, Delete) 메서드의 뼈대를 정의한 인터페이스
- `Valorant`: 게임 기록 한 판의 세부 정보를 담고 있는 데이터 클래스
- `ValorantManager`: `ICRUD` 인터페이스를 구현하며, `ArrayList`를 이용해 데이터를 관리하고, 파일 입출력 및 부가 기능(검색, 통계, 필터링)을 수행하는 클래스

## 4. interface 사용 이유

`ICRUD` 인터페이스를 사용하여 데이터 관리 클래스가 반드시 구현해야 할 기본 동작(추가, 조회, 수정, 삭제)을 강제했습니다. 이를 통해 개발 과정에서 필수 기능의 누락을 방지할 수 있으며, 추후에 다른 종류의 데이터를 관리하는 클래스(예: 롤 전적 트래커)가 추가되더라도 동일한 메서드 이름을 사용하게 되어 코드의 일관성과 다형성(Polymorphism) 확보가 가능합니다.

## 5. overriding / overloading 적용 부분 설명

- **Method Overriding (오버라이딩)**: 
  - `ValorantManager` 클래스에서 `ICRUD` 인터페이스의 추상 메서드들(`addData`, `printData`, `updateData`, `deleteData`)을 실제 로직으로 재정의하여 사용했습니다.
  - `Valorant` 클래스에서 최상위 클래스인 `Object`의 `toString()` 메서드를 재정의하여, 객체 출력 시 사용자가 읽기 편한 전적 요약 문자열 형태로 출력되도록 했습니다.
- **Method Overloading (오버로딩)**: 
  - `Valorant` 클래스의 생성자에서 매개변수가 없는 기본 생성자와 모든 필드를 초기화하는 매개변수가 있는 생성자를 Overloading 을 통해 중복 정의하였습니다.

## 6. 추가 기능 3가지 설명

1. **날짜 기준 검색 기능 (**`searchByDate`**)**: 사용자가 특정 날짜(ex: 2026-05-02)를 입력하면, 해당 날짜에 플레이한 게임 기록만 필터링하여 표 형식으로 출력
2. **게임 플레이 기록 통계 (**`showGamePlayStatistics`**)**: 기록된 모든 데이터를 분석하여 총 플레이 판수, 가장 많이 플레이한 요원과 맵, 전체 판수의 평균 K/D/A와 평균 헤드샷 비율을 계산하여 전적 요약 결과를 출력
3. **헤드샷 비율 필터링 (**`filterByHeadshotRate`**)**: 사용자가 보고싶은 최소 헤드샷 비율을 입력하면, 해당 비율 이상을 기록한 판들만 모아서 출력

## 7. 구현 과정에서 어려웠던 점

1. **통계 기능 구현 시 최빈값(Most) 찾기**: 단순히 리스트를 정렬하는 것이 아니라, 요원과 맵의 플레이 횟수를 카운트하기 위해 `HashMap`을 도입하여 이름(Key)별로 횟수(Value)를 누적 저장하고, 이를 다시 `Map.Entry` 리스트로 변환하여 `Comparator`로 내림차순 정렬하는 방식을 적용하는 과정이 복잡해서 어려웠습니다.
2. **콘솔 출력 UI(표) 정렬 문제**: `printData()`를 통해 데이터를 표 형태로 출력할 때 글자 폭이 달라 세로줄(`|`)이 삐뚤어지는 문제가 발생... 이를 해결하기 위해 `String.format()`의 `%-10s`, `%-4d` 등의 포맷 지정자를 활용하여 고정 너비를 할당하며 미세하게 조정하여 깔끔한 표를 완성하는 데 많은 테스트가 필요했습니다.

## 8. 수업 회고 및 느낀점

- **새롭게 배운 점**: `PrintWriter`와 `Scanner`를 이용한 파일 입출력을 통해, 프로그램이 종료되어도 데이터가 남게 저장하는 기능을 구현하며 새로운 기능을 익혔습니다. 또한 통계를 구현하며 사용하게 된 HashMap 등 새로운 기능들을 익힐 수 있어 많은 도움이 되었습니다.
- **수업 방식에 대한 건의사항**:  미니 프로젝트 과제가 많으면 기능이나 자바의 전체적인 구조를 익히는데 있어 도움이 많이 되는 것 같습니다. 수업 시작부터 어떤 주제로 만들지 고민하면서 학기를 시작했으면 조금 더 처음부터 고민하고 생각하는 과정이 있어 도움이 많이 되고 흥미가 더 생겼을 것 같습니다.
